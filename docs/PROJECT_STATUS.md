## Sửa EPERM khi khởi động frontend dev trên Windows — 06/11/2026

- Người dùng báo `EPERM unlink` tại `.next-local/dev/build/chunks/pool_entry-…js`. Đọc ACL đúng file và thư mục cha xác nhận owner là tài khoản sandbox; nhóm Windows Users có Write/ReadAndExecute nhưng không có quyền Delete. Lần kiểm tra trước chạy dưới sandbox nên khởi động được, chưa phản ánh quyền của tài khoản người dùng.
- `front/next.config.ts` đổi output trên Windows sang `.next-local-<hash-tài-khoản>/`, dùng danh tính thực từ `whoami.exe` và SHA-256 rút gọn; dev/build/start cùng tài khoản dùng cùng output. Không dùng biến USERNAME (thực tế sandbox kế thừa `Admin`), không thay ACL/xóa cache cũ/chạy quyền Administrator. `os.userInfo()` trả lỗi `uv_os_get_passwd ENOMEM` trong sandbox nên dùng `whoami.exe` trực tiếp, không qua shell. Linux giữ `.next-local/` cố định cho build/runtime khác UID.
- `.gitignore` bổ sung output mới; `tsconfig.json` giới hạn source/test/config và generated types mới để không thu cache cũ vào kiểm tra. ESLint đã bỏ qua `.next*/**`. README frontend và tài liệu kiến trúc cập nhật cách chạy và giới hạn build/start cùng tài khoản Windows.
- Đã boot dev hai lần dưới sandbox bằng output mới, cả hai đều Ready; lần khởi động lại GET `/` trả 200. Smoke dev 8 trang và hai luồng điều hướng/giỏ/checkout qua, không pageerror. Kiểm ESLint riêng `next.config.ts` qua. Trong lúc kiểm full build/format, workspace được bổ sung `src/catalog/*` và rewrite API song song: build dừng tại import `./model` chưa tồn tại ở thời điểm kiểm, format báo `presentation.ts`; không sửa hoặc ghi đè phần công việc đó. Chưa xác nhận lại toàn build với mã catalog mới, hoặc boot trực tiếp bằng tài khoản Windows của người dùng. Đã dừng các dev server do lượt kiểm này tạo để người dùng chạy lại không vướng cổng/lock.
